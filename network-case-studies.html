CASE STUDY 01 / 03

Segmented office network

VLANs · DHCP relay · guest access policy

Design a small office network for staff, CCTV and guests. Centralise address allocation in a services VLAN, retain access to DNS and isolate guest clients from internal subnets. Scope is internal connectivity; Internet access, NAT and firewall deployment are not included.

Staff / CCTV / Guest
SW1 · VLANs 20/30/40
R1 · 802.1Q gateway
Services · VLAN 10

01 / Network plan

ComponentDesign
VLAN 10 / Services192.168.10.0/24 · R1 .1 · DHCP .10 · DNS .53 · Web .80
VLAN 20 / Staff192.168.20.0/24 · gateway .1 · DHCP .100–.254
VLAN 30 / CCTV192.168.30.0/24 · gateway .1 · DHCP .100–.254
VLAN 40 / Guest192.168.40.0/24 · gateway .1 · DHCP .100–.254
Physical connectionsR1 Gi0/0 ↔ SW1 Gi0/1. Staff Fa0/1; camera/test PC Fa0/2; guest Fa0/3. DHCP-SRV Gi0/0 ↔ SW1 Fa0/10; DNS ↔ Fa0/11; web ↔ Fa0/12.

02 / Fault isolation & solution

Designed symptomDiagnosisResolution
Staff has no leaseCheck access VLAN, trunk membership, router subinterface, helper IP and DHCP server return route.Carry VLAN 20; relay to 192.168.10.10; give the DHCP server a route back through R1.
CCTV segment is unreachableInspect VLAN 30 on both the switch trunk and router subinterface.Allow VLAN 30 and match dot1Q tag 30 to its gateway.
Guest can reach staffInspect ACL entries, their order and interface direction.Apply GUEST-IN inbound on Gi0/0.40. Permit DHCP renewal and DNS exceptions before the internal-subnet deny.

05 / Technical reasoning

DHCP across VLANs needs both a working relay path and a server return path. An isolation policy needs explicit service exceptions; a blanket deny can break renewal or DNS.

CASE STUDY 02 / 03

Two-site OSPF fault isolation

Layer 1/2 checks · OSPF adjacency · forward & return routes

A troubleshooting design for two sites affected by three independent faults: an administratively disabled WAN interface, mismatched OSPF areas and a missing remote LAN advertisement. The solution separates neighbor formation from route propagation.

Vienna LAN · 192.168.10.0/24
R1 · 10.0.12.1/30
R2 · 10.0.12.2/30
Linz LAN · 192.168.20.0/24

01 / Network plan

ComponentDesign
WANR1 Gi0/1 ↔ R2 Gi0/1; 10.0.12.0/30; Area 0
Vienna endpointPC-A 192.168.10.10/24; gateway 192.168.10.1; LAN to R1 Gi0/0
Linz endpointPC-B 192.168.20.10/24; gateway 192.168.20.1; LAN to R2 Gi0/0
Lab assumptionsBlank routers for full configuration below. On an existing faulted lab, first remove conflicting interface addresses and OSPF network statements. Match link masks, timers and MTU.

02 / Fault isolation & solution

Designed symptomDiagnosisResolution
No neighbor after startupshow ip interface brief; ping the directly connected WAN IPEnable the disabled WAN port and confirm both ends are up/up.
WAN reachable, adjacency absentCompare show ip ospf interface and the OSPF network statementsUse Area 0 on both WAN interfaces. Remove an obsolete Area 1 WAN statement before adding the Area 0 statement.
FULL neighbor, remote host unreachableshow ip route ospf on both routers; inspect endpoint gatewaysAdvertise both LANs; verify a forward route and a return route.

CASE STUDY 03 / 03

Resilient switching & recovery

LACP · trunk consistency · STP root control · link-failure test

Design a two-link EtherChannel between access switches. Repair passive/passive negotiation, missing VLAN membership and a native-VLAN mismatch; deliberately choose the primary STP root. Test service continuity when one physical bundle member fails.

PC-A · VLAN 20
S1 · Po1 / Gi0/1–2
S2 · Po1 / Gi0/1–2
PC-B · VLAN 20

01 / Network plan

ComponentDesign
LinksS1 Gi0/1 ↔ S2 Gi0/1; S1 Gi0/2 ↔ S2 Gi0/2. Match member speed/duplex and local settings.
EndpointsPC-A on S1 Fa0/1: 192.168.20.11/24; PC-B on S2 Fa0/1: 192.168.20.12/24. Same-VLAN test; no router required.
ManagementS1 VLAN 10 SVI: 192.168.10.11/24; S2: 192.168.10.12/24.
STP designS1 priority 4096; S2 priority 8192 for VLANs 10 and 20. Native VLAN 99 on both peers. Two physical members form one logical STP port.

02 / Fault isolation & solution

Designed symptomDiagnosisResolution
Links up, no bundleshow etherchannel summary; inspect LACP modeMake S1 active and S2 passive or active; passive/passive does not start negotiation.
Bundle formed, VLAN 20 failsshow interfaces trunk; compare allowed VLANsCarry VLAN 20 on both Port-channels and keep local member settings consistent.
Native mismatch / wrong rootCompare native VLANs; show spanning-tree vlan 20Set native VLAN 99 on both sides. Use a lower valid S1 bridge priority. Native mismatch is checked separately from LACP negotiation.

04 / Acceptance tests

Expected results, not captured execution output. Add actual before/after evidence after a personal lab run.

TestVerification actionExpected condition
Bundle healthshow etherchannel summaryPo1 is Layer 2 / in use (commonly SU); both links bundled (commonly P).
VLAN / rootshow interfaces trunk; show spanning-tree vlan 20Both peers carry VLANs 10,20,99; native VLANs match; S1 is root for the designed VLANs.
Single-member failureRun PC-A → PC-B ping; shut S1 Gi0/1; inspect Po1 and repeat pingPo1 remains operational through Gi0/2; traffic can continue after any transient loss. Available aggregate capacity is reduced.
Restorationno shutdown on Gi0/1; show etherchannel summaryBoth member links rejoin the bundle.

05 / Technical reasoning

Port-channel health, VLAN forwarding and STP root selection are separate checks. A surviving bundle member can preserve connectivity, but a two-member bundle does not double the bandwidth of every individual flow.
